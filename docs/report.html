Harness Bench Report
Engineering Test Bench · terminal-bench 2.0 · 27 tasks

Which agent harness gets the most out of each model?

FINAL · 3 Nov 2026 · reruns included · Claude Code via gateway added 6 Nov 2026
  • Ten agent harnesses ran the same 27 IT, e-commerce and SaaS tasks on six models.
  • Every ratio divides by a reference on the same tasks: 0.80× means 20% less than the reference.
  • The overall reference is Claude Code on Opus 5.5 medium.
  • Harnesses are compared with Claude Code on Claude models and with Goose on the other models, at the same model and effort.
  • Models are compared with the same harness on Opus 5.5 medium.

Executive insights

  • Model choice correlates more with task success; harness choice correlates more with cost.On Claude models every harness passed 25–27 of 27 tasks, a spread too small to tell apart at this sample size. Cost varied widely: at Opus medium, Pi cost 31% less than Claude Code, Goose 21% less, and Cline 60% more.
  • Sonnet 5.5 stood out among the mid-tier models on these terminal-bench tasks.Across the 8 harnesses that ran every model, Sonnet passed 209 of 216 (97%), against 92–94% for Kimi K3, GPT-6.1 Terra, DeepSeek and Grok, and 80% for GLM. It was also the fastest (1.6 min median per task, against 2.1–5.6) and tied with Terra as the cheapest (2.6¢). The pass gap to the next models is a few tasks; the cost and speed gaps are larger. For scale, Opus medium passed 211 of 216 at about three times Sonnet's cost.
  • Claude Code was the fastest harness on Claude models, not the cheapest.The other harnesses took 1.3–2.2× as long as Claude Code at Opus medium. Where people wait on the agent, that speed may justify its cost; for unattended batch work, Pi and Goose reached the same pass counts for less.
  • Open models cost less, and each tended to do best on a particular harness.The top harness differed by model: Kimi K3 on Pi (27 of 27, among the cheapest and fastest), DeepSeek V4.1 Flash on OpenCode or Terminus-2 (26 of 27 at the lowest cost), GLM 5.3 on Cline (24 of 27). GLM had the widest spread across harnesses (20 to 24). Most of these margins are one to four tasks, so treat each pairing as a starting point to confirm, not a settled ranking.
  • Grok 4.7 was the most expensive and slowest option in this test.On Goose it cost 1.9× Opus medium and took 3.3× as long, with 26 vs 27 passes. Some of the slowness coincided with an overloaded test machine; the cost gap held after the reruns.
  • Some agents with internet access looked up the benchmark's answers.In 12 runs, mostly on DeepSeek, the agent downloaded the benchmark's own answer key and used it; we count those as fails. Published scores for internet-connected agents may be inflated, and the same behaviour in production means fetching and running unvetted code, so internet access warrants a deliberate policy.

Claude Code through a LiteLLM gateway (6 Nov 2026)

A second, smaller experiment ran Claude Code 2.1.312 through a self-hosted LiteLLM gateway on the same 27 tasks, one attempt per task. These runs show what the route correlated with, not what the model did. Ratios divide by the reference, using only the tasks both arms ran (0.80× means 20% less); time ratios compare summed trial minutes, not the medians shown, and the medians here are per task (each task's latest trial), where the matrix uses per-trial medians. Translated means the gateway converts Claude Code's Anthropic-format requests into the provider's own API; native or pass-through means the provider accepts them directly. Rows compared with Goose change the harness as well as the route.   • The control kept Opus within one trial of direct. Through the gateway Claude Code passed 26 of 27 against 27 of 27 direct, and every trial used Opus 5.5 only. The miss was sanitize-git-repo (reward 0, not a timeout); the direct Claude Code run on that task passed. The gateway run cost 1.48× the direct run, and its uncached input was about 2.1× higher (696k against 333k tokens) while total prompt and cache-read tokens were similar. The cause was not established.
  • Translation correlated with four timeouts on DeepSeek. The translated route passed 23 of 27 and the native route 26 of 27, with the same model behind both. All four translated misses (cobol-modernization, mailman, financial-document-processor, headless-terminal) were agent timeouts, and the translated route took 1.51× the total minutes.
  • Kimi K3 passed only on the pass-through route. The translated route failed on Fireworks rejecting thinking_blocks (two early trials were excluded). After the gateway forwarded to Fireworks' own Anthropic endpoint, Kimi passed 25 of 27: one plain fail (sqlite-with-gcov) and one API error (financial-document-processor).
  • Terra's cost first read $11.41 and was $2.01. LiteLLM 1.83.7 did not report cached tokens on the Responses-API translation, so the bench priced about 9.9M cached prompt tokens as fresh input. The gateway's own spend log (564 calls, all matched to trials) gave the corrected cost, and the ledger now carries both figures. Terra passed 26 of 27 (miss: sanitize-git-repo).

Harbor pointed every Claude Code model alias and its subagent model at each arm's own model; the Opus control put back Haiku, Sonnet and Claude Code's default subagent choice, as the direct arm uses them. DeepSeek and Kimi ran at high effort, Terra and Opus at medium. Costs are token counts at list prices. A trial that hit the agent time limit counts by its tests, as in the rest of this report: Kimi and Terra each had two timeouts (kv-store-grpc, pypi-server) whose tests passed afterwards, and the four translated DeepSeek timeouts failed their tests. Three Opus control trials failed at setup because the container could not resolve the package mirrors (apt-get update failed before the agent started); they were rerun on the same arm and all three passed. With one attempt per task, a one-task difference is too small to read much into.

How the results were checked

Checked

Prices

Every rate used here matches the providers' price pages as of 3 Nov 2026. Costs are token counts × those rates. Long-context price tiers are not applied, so very long requests are priced slightly low.

Checked

Kilo and OpenCode on Opus

Their Opus high and medium trials often reused a prompt cache written minutes earlier by another trial, which makes them look cheaper than Opus low. This is real cache behaviour, not a counting bug; costed as if every trial started cold, high and medium would be 1.4–1.9× low.

Checked

Cost records

Every trial with token counts is costed, DeepSeek Harness included. The report recomputes cost from tokens rather than trusting each harness's own figure.

Settled

Our own faults and answer lookups

Trials lost to our setup were excluded and rerun; provider stalls count as fails. Agents that fetch the benchmark's own answer files are flagged automatically, confirmed by hand and counted as fails. Fetching a real upstream fix, such as a CVE patch, is allowed.

Rerun

37 trials (2%) rerun

Trials that may have failed for reasons on our side were rerun: 3 where the harness install could not reach github.com (all 3 passed), 14 fails while the CPU was busy (7 passed), and 20 timeouts from a period with no CPU record (11 passed). Ten passes from the same period were rerun as a control, and 9 passed again, so a single rerun is noisy. Both attempts count: each task's result is the average of its trials.

Method. terminal-bench 2.0 on Harbor 0.25.0, one attempt per task, two where a trial was rerun (each task's result is the average of its trials). Open models (DeepSeek, GLM, Kimi) run through Fireworks at high effort; Terra and Grok at medium. Claude Code ran directly only on Claude models; its Kimi K3, Terra and DeepSeek results (†) came through a LiteLLM gateway (see the gateway section). On the other models Goose is the reference harness. DeepSeek Harness runs only on DeepSeek, so it has no model comparison. A pass is the task's own tests passing. Medians are per trial.
